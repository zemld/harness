# Кодовый агент

LLM-агент, который мы пишем в коде с помощью соответствующего фреймворка.
Имеет свои системные инструкции, инструменты.

## Что такое хороший кодовый агент

Хороший кодовый агент имеет понятные инструкции.

### Системный промпт

Системный промпт описан четко, кратко и по делу.
Он объясняет что из себя представляет агент и как он должен действовать: что приходит на вход, и что должно быть в результате.
Можно использовать `html` теги для разметки.
Можно указывать обязательные правила.

#### Пример 1

```md
Ты агент-закупщик. Твоя задача — вести закупочный процесс так, чтобы заказчик получил подходящие товары или услуги на согласованных условиях.
```

#### Пример 2

```md
<role> Ты — агент поиска поставщиков для закупки. Ошибочный поставщик дороже недобора: точность важнее квоты. </role>

<task> Найди поставщиков под ТЗ и верни по каждому подтверждённые данные. </task>

<grounding> Каждый поставщик и каждый факт — только со страницы, которую ты реально открыл в этой сессии. Ничего из общих знаний. Агрегаторы и маркетплейсы — лишь для обнаружения кандидатов; перед зачётом подтверждай каждого на первичном источнике. </grounding>

<process> Варьируй запросы — синонимы товара/услуги, тип поставщика (производитель/дистрибьютор/интегратор), широта категории. Останавливайся, когда найдено нужное количество подтверждённых поставщиков либо исчерпан заданный бюджет поиска. </process>
```

### Описание инструментов

Описания инструментов показывают, что делают сами инструменты. Без внутренних подробностей. Агенту важен лишь бизнес-эффект, зачем использовать инструмент.

#### Пример

Для инструмента сохранения найденных поставщиков `save_found_suppliers` можно написать так:

```md
Сохраняет найденных поставщиков в БД. Заменяет весь существующий список поставщиков.
```

Этого достаточно. Смысл аргументов лучше описывать также кратко в `JSON` схеме аргументов.
Важно также не просто пересказывать название инструмента, а объяснять его бизнес-значимость.

## Антипаттерны

- Писать конкретный воркфлоу в системном промпте.
- Описывать параметры инструмента в описании инструмента. Это дублирование путает и просто тратит токены.
- Описывать что под капотом делает инструмент. Агенту важно только как и зачем можно использовать его, а не детали реализации.
